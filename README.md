# 质因数分解器

一个小工具，两种玩法：**分解工具**判断质数、分解质因数；**猜一猜**随机出题，考你一眼看出质数还是合数。

![预览](preview.png)

## 两种模式

页面顶部可以切换，两种模式互不干扰。

### 分解工具

输入 1 ~ 100000000（1 亿）的整数：

- **质数**：只显示「质数」两个字，不附加任何解释
- **合数**：直接给出分解式，如 `360 = 2³ × 3² × 5`、`100000000 = 2⁸ × 5⁸`
- 不罗列中间步骤，一步到位
- 输入校验：空输入、小数、负数、0、超过 1 亿都会给出明确提示
- 1 单独处理：既不是质数也不是合数

### 猜一猜

- 随机给出一个 **100 ~ 10000 之间的奇数**（且**不是 5 的倍数**），猜它是质数还是合数
- **3 的倍数出现得更少**：原本占三分之一，现在只占约 **1/9**
- 每组题数**可选 10 题或 20 题**，切换后立即开始新的一组
- 猜对显示 ✓，猜错显示 ✗
- 如果是合数，额外给出该数的分解
- 答完给出这一组的正确率
- 顶部有小圆点记录每题对错，随时看到进度
- 同一组内的数字不会重复

## 算法

**为什么不建全量质数表？** 支持到 1 亿时，如果为每个数存「最小质因数」，
需要一张 1 亿项的 `Uint32Array`，也就是 **400 MB 内存**——页面根本打不开。

所以改用**小质数表 + 试除**：

1. 启动时只筛出 `1 ~ √10⁸ = 10000` 以内的质数，共 **1229 个**（几 KB）
2. 分解时用这 1229 个质数逐个试除
3. 任何 ≤ 1 亿的合数，必定有质因数 ≤ √n ≤ 10000；扫完整张表还没除尽的剩余部分，**一定是质数**

最坏情况（输入本身是大质数）也只要 1229 次除法：

| 场景 | 实测耗时 |
| --- | --- |
| 页面加载 + 建表 | 约 1 ms |
| 大质数（最坏情况） | 约 **3 µs** |
| 大合数（如 100000000） | 约 0.2 µs |

猜一猜模式里的数字都在 1 万以内，判断同样是瞬间完成。

### 出题时的加权抽样

3 的倍数在原候选池里正好占 1/3（1320 / 3960）。把它降到 1/9 用加权抽样实现：
非 3 的倍数权重为 1，3 的倍数权重为 W，由

```
M·W / (M·W + N) = 1/9      M = 1320 个 3 的倍数，N = 2640 个其余数字
```

反解出 W = 0.25。这样即使以后修改取值范围，目标比例依然成立，不需要手调常数。
抽样时若抽到 3 的倍数，再按 W 的概率决定是否采用，否则重抽——同组内仍保证不重复。

## 本地使用

直接用浏览器打开 `index.html` 即可，不需要安装任何东西。

## 部署到 GitHub Pages

1. 在 GitHub 新建一个 **Public** 仓库，不要勾选初始化 README。
2. 在本文件夹里执行：

   ```bash
   git init
   git add .
   git commit -m "质因数分解器"
   git branch -M main
   git remote add origin https://github.com/你的用户名/prime-factor.git
   git push -u origin main
   ```

3. 打开仓库 → **Settings** → 左侧 **Pages** → Source 选 `Deploy from a branch`，
   Branch 选 `main` + `/ (root)`，点 **Save**。
4. 等 1 ~ 2 分钟，访问 `https://你的用户名.github.io/prime-factor/`

> 注意：主页文件名必须是 `index.html`，且仓库必须是 Public。
