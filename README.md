# 质因数分解器

输入 1 ~ 100000000（1 亿）的整数，瞬间判断它是**质数**还是**合数**。
合数直接给出质因数分解式，质数只显示「质数」两个字。

![预览](preview.png)

## 功能

- **质数**：只显示「质数」两个字，不附加任何解释文字
- **合数**：直接给出分解式，如 `360 = 2³ × 3² × 5`、`100000000 = 2⁸ × 5⁸`
- **不罗列中间步骤**，一步到位给结果
- **范围**：1 ~ 100000000
- **输入校验**：空输入、小数、负数、0、超过 1 亿都会给出明确提示
- **1 单独处理**：1 既不是质数也不是合数
- **可分享**：打开 `index.html#360` 直接显示 360 的结果
- **纯前端**：单个 HTML 文件，无依赖、无需联网，双击即可使用
- **自适应**：自动适配手机屏幕和深色模式

## 算法

**为什么不建全量质数表？** 支持到 1 亿时，如果为每个数存「最小质因数」，
需要一张 1 亿项的 `Uint32Array`，也就是 **400 MB 内存**——页面根本打不开。

所以改用**小质数表 + 试除**：

1. 启动时只筛出 `1 ~ √10⁸ = 10000` 以内的质数，共 **1229 个**（几 KB）
2. 分解时用这 1229 个质数逐个试除
3. 任何 ≤ 1 亿的合数，必定有质因数 ≤ √n ≤ 10000；扫完整张表还没除尽的剩余部分，**一定是质数**

最坏情况（输入本身是大质数）也只要 1229 次除法：

| 场景 | 实测耗时 |
| --- | --- |
| 页面加载 + 建表 | 约 1 ms |
| 大质数（最坏情况） | 约 **3 µs** |
| 大合数（如 100000000） | 约 0.2 µs |

## 本地使用

直接用浏览器打开 `index.html` 即可，不需要安装任何东西。

## 部署到 GitHub Pages

1. 在 GitHub 新建一个 **Public** 仓库（例如 `prime-factor`），不要勾选初始化 README。
2. 在本文件夹里执行：

   ```bash
   git init
   git add .
   git commit -m "质因数分解器"
   git branch -M main
   git remote add origin https://github.com/你的用户名/prime-factor.git
   git push -u origin main
   ```

3. 打开仓库 → **Settings** → 左侧 **Pages** → Source 选 `Deploy from a branch`，
   Branch 选 `main` + `/ (root)`，点 **Save**。
4. 等 1 ~ 2 分钟，访问 `https://你的用户名.github.io/prime-factor/`

> 注意：主页文件名必须是 `index.html`，且仓库必须是 Public。

## 测试

```bash
node test.mjs
```

验证策略（1 亿个数无法逐个暴力试除，所以分三层）：

1. **全量结构验证**：2 ~ 1,000,000 每个数都检查「因子全是质数」且「乘起来等于原数」，
   由**唯一分解定理**可断言这就是唯一正确的分解
2. **大范围抽样**：1e6 ~ 1e8 随机抽 200,000 个做同样的结构验证
3. **独立对照**：另建一张完整的 1 亿质数位图（100 MB），与页面算法完全独立，
   用来校验素数判定和「哪个数确实是质数」

```
脚本加载 + 质数表预处理：1.02 ms
独立筛表构建：1195 ms，π(10⁸) = 5761455 ✓ 与已知值一致
全量验证 2~1,000,000：全部通过 ✓（272 ms）
随机抽样 200,000 个（1e6 ~ 1e8）：全部通过 ✓（172 ms）
参考实现比对（102999 个数）：全部一致 ✓
质数仅输出"质数"两字：全部通过 ✓
```
